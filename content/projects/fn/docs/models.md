fn 0.5 以连接管理模型：`{connectionId,modelId}`。每个连接保存 provider、端点、认证方式和配置，凭证独立保存。

## API Key 与订阅

从服务商预设创建连接，或添加兼容协议的自定义端点。API Key 与订阅登录在同一界面管理。OAuth 登录、刷新和模型协议复用锁定版本的 Pi / dsh；同一 provider 可创建多个账号，原始 provider 名称保持不变。

为账号设置清楚的名称，避免误选。正常 token 刷新保留连接身份；改变账号身份或端点应建立新连接。缺少凭证不会借用其他账号或进程环境中的密钥。

## 账号目录与已添加模型

预设目录表示协议已知模型，不代表账号一定有权限。动态目录从所选账号查询，支持刷新。将需要的模型添加到列表不会发起生成请求；调用时才验证网络与模型权限。

插件和手机使用“已添加模型”。手机目录为已添加列表与当前连接可用目录的交集，没有可选模型的连接隐藏。离线期间模型被移除，排队的新建/切换命令会在宿主拒绝，不会静默切换其他账号。

## 会话绑定

一个 Session 固定一个连接，同连接可切换模型；更换账号或端点需要新会话。删除已添加模型不会改写已有会话绑定。标题生成和其他无 Agent 操作也必须显式选择连接。

## 凭证

使用权限受限的每连接凭证文件，保留原子写入和刷新锁。凭证不通过业务 API 返回前端。不要把旧版 `platform.json` 或登录文件复制到新数据目录。

已有订阅的真实模型请求、工具循环与重启恢复已验收；所有服务商的新账号登录、强制过期刷新和权限组合并未逐一实测。
